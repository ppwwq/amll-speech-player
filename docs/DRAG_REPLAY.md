# Drag selection and same-sentence replay

Drag regions now meet halfway between one sentence's bottom edge and the next sentence's top edge. Geometry comes from AMLL's cached, unscaled row positions and measured heights, ordered by their layout top. The preview's existing scale spring therefore cannot move the selection boundary. A guide exactly on a boundary selects the following sentence deterministically. Background/empty rows and invalid audio timestamps retain their existing handling.

The former nearest-centre rule could choose a short neighbour while the guide was still inside a long wrapped sentence. Against `9cfe2dd`, the new browser regression reproduced this at 1280×900: the current long row had top 151px and height 245px, the next short row began at 396px, and the guide at 394px incorrectly chose the short row (16 seconds) instead of the current row (8 seconds). The corrected gap boundary keeps the long row selected until the guide crosses 396px. See [baseline evidence](results/drag-replay-baseline.json).

The existing release path already sent one `line-activate` event and assigned the audio time even when the selected row was the currently active row; there was no same-index skip to remove. That path is preserved and explicitly documented. A valid drag ending on the current sentence seeks to its offset-corrected start, restarts the lyric word clock, and preserves playing/paused state. No intermediate preview seeks, extra tap action, release inertia or automatic loop is added.

The gesture threshold is unchanged: vertical displacement must exceed 10 CSS pixels and dominate horizontal movement. An ordinary click or movement of at most 10px remains a tap, subject to the existing tap-duration and double-tap rules. Pointer cancellation, leaving the transcript, multi-touch, changed media/delay and rotation retain their existing cancellation behavior.

`tests/drag_replay.py` uses actual Chromium mouse/CDP touch input on synthetic WAV/LRC at desktop 1280×900, tablet landscape 1024×768, portrait 768×1024 and phone 390×844. The tablet page remains loaded while rotating. It checks both sides of tall/short and short/tall boundaries, holds targets while preview scaling settles, replays a half-finished current sentence, previews the next sentence then drags back, repeats without a setup seek between gestures, checks 0/10/11px thresholds, and cancels while paused/playing. Each successful release must generate exactly one seek and each cancellation none. These four scenarios passed with 24 same-sentence releases, 32 held boundary samples, 12 threshold gestures and eight cancellation gestures. See the [measured results](results/drag-replay-results.json).

This change also passed TypeScript checking, 18 Node tests and the production build; the existing drag-seek suite, four native-preview scenarios, five UI/MP3/LRC/single-double-tap layouts, 16 top-layout configurations and 20 seek-order groups were rerun successfully. No browser page errors were recorded. The separate 84-case tap-playback and full local-session browser suites were not rerun for this selection-only change; their event/storage implementations are unchanged.

All media are synthetic. These checks do not constitute physical iPad Safari testing. The glass UI, local-session storage and top layout are unchanged by this implementation.
