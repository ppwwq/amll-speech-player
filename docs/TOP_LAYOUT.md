# Transcript clearance below the toolbar

The confirmed defect was overlap in the wide/two-column layout (including tablet portrait widths above 768px). The lyric panel occupied the full viewport from y=0, and the renderer had a -15px top margin plus 20px padding. At 1024×712, its measured bounds were y=-15 and height=732. A previous sentence was hit-testable at (800,25), behind the fixed toolbar. The closed local-save summary extended to y=104. This allowed scrolling lyrics to appear behind the top controls and be obscured by them.

The toolbar's computed background was transparent, with no background image, mask, shadow or backdrop filter on the full-width container. Its individual glass buttons retain their blur. The runtime layer inspection found no full-width black CSS overlay; the source's black gradients belong to the optional album-cover long-shadow effect. AMLL word masks affect text opacity rather than painting a black header. A full-width dark horizontal strip was not reproduced in Chromium, so that part of the reported screenshot remains unconfirmed.

The supplied screenshot's pixels could not be downloaded by the authorized Library transfer helper (two attempts returned `download failed`). This investigation used the reported appearance plus local source/runtime evidence; it does not claim a pixel comparison against that screenshot. Black space outside the web view's rounded corners belongs to the surrounding window/system surface and is distinct from an overlay inside the page. Whether the reported strip is browser/status-bar styling, background rendering or another Safari-specific effect still requires a device check; the PWA status-bar metadata was not changed speculatively.

The fix reserves space for both top control rows using a shared safe-area-aware top offset. With the normal 10px offset, the wide transcript starts at y=112 and its height ends at the original viewport bottom. The old renderer margin/padding offsets are removed, including the competing inline padding assignment. Narrow portrait keeps its existing 208px transcript start and moves consistently if the resolved top inset increases. No dark backing panel or new gradient was added. The original glass styles, background renderer and gesture implementation are unchanged.

`tests/top_layout.py` checks the same loaded page across eight sizes (1280×900, 1024×768, 768×1024, 820×1180, 390×844, 844×390, 1024×712 and 1536×1067). It checks normal and injected 34px resolved top offsets, actual hit testing throughout the header, complete active-line visibility, bounded layout after rotation, and cancellation when a touch drag exits into the header. The injected offset tests CSS geometry; it does not emulate Safari's operating-system safe-area calculation. See [measured results](results/top-layout-results.json) and [baseline layer inspection](results/top-layout-baseline.json).

Validation on the production build passed TypeScript checking, all 17 Node tests, the 16 header-layout configurations above, five existing UI/import/gesture viewports, the drag-seek cancellation suite, four native drag-preview scenarios, 20 seek-order groups and 84 tap-playback cases. There were no browser page errors or playback console errors. The UI checks include decoded synthetic MP3/LRC, single/double taps, drag release and the translucent time-only badge.

All browser evidence uses synthetic media in Chromium. Physical iPad Safari, installed standalone mode and the original screenshot's dark strip have not been verified.
