# Keep selected sentences in place

Double-tapping a sentence, activating it with Enter/Space, or releasing a valid drag selection now retains the transcript's visible position. Playback and highlighting continue at the selected time; paused playback stays paused. Selecting the same sentence again replays its start exactly once. The view remains held until **Follow** is pressed, including after subsequent seeks, browsing, cancellation and the old five-second idle interval. Loading a new caption document resets its layout. This temporary viewing state is not saved as a preference.

Ordinary wheel/browse-mode scrolling without committing a sentence keeps its existing inertial scrolling and five-second idle return. The current drag-selection geometry, preview spring, translucent time badge, sorting, single-tap playback action, media checkpoint and preference storage paths are retained.

## Confirmed causes and targeted changes

`setupLyricEvents()` passes line activation to `seekAudio(..., true)`. Previously, its default `follow=true` called `resetScroll()` before updating the audio clock. That cleared manual browsing and the scroll offset, so AMLL placed the newly active sentence at the configured alignment. Separately, `onPointerUp()` called `scheduleFollow()`, which always armed a five-second reset whenever manual browsing was active. Omitting only the immediate reset would therefore still jump later.

The adapter now distinguishes temporary browsing from a committed selection with a transient `positionHeld` flag. A validated line seek calls `holdPosition()` before changing the clock. It freezes the manual layout anchor and cancels inertia and the idle timer. It uses the last rendered anchor and the selected row's actual spring position to preserve that displayed position. A one-time layout correction before paint accounts for a moving spring or an interlude spacer disappearing on seek. The existing `renderLayout()` manual-anchor path continues to render AMLL's active rows and word animations. No second renderer, scroll system or animation loop was added.

`scheduleFollow()` does not arm an idle reset while a selection is held; unrelated seek controls also respect the held view. Explicit **Follow** clears the flag through the existing reset path and aligns to the current audio clock. Caption replacement also uses that reset path. Upstream AMLL input handlers remain disabled by the existing `allowScroll=false`, so its own scroll timeout is not armed by these gestures.

## Verification

`tests/selection_position.py` measures DOM sentence centres and cached layout positions before/after real mouse or touch selection. It covers top/middle/bottom placements, wrapped sentences, both playback states, forward/backward jumps, repeated same-row double taps, drag releases in both directions, playback during a follow animation, opening silence/interlude spacing, real waits longer than five seconds, browsing/cancellation after selection, ordinary idle follow, and explicit Follow alignment. Desktop, tablet and narrow-phone viewports are included. Existing gesture and settings tests provide additional regression coverage.

All 39 selection-position groups passed with no page errors; [results](results/selection-position-results.json) record each scenario. Position assertions allow under 2px of DOM rounding/scale variation and under 0.1px of cached layout movement. Removing the opening-interlude spacer without the one-time correction was separately reproduced as a 60px upward movement on synthetic SRT captions.

TypeScript checking, 25 Node tests and the production build passed. All eleven executed browser suites passed: selection position, preferences (48 controls/49 fields and 12 scenario groups), local-session storage (23 cases), general playback/virtualization, drag seek, native drag preview, same-sentence drag replay (four viewports), UI (five viewports), header layout (16 configurations), seek ordering (20 groups), and tap playback (84 cases). [Suite results](results/selection-regression-results.json) list the commands. Existing drag-release assertions now expect the held view; independent gesture test setups explicitly reset following instead of assuming that any seek clears the prior selection. The independent file-import suite was not rerun for this interaction-only change.

The browser tests run against a local production build with synthetic audio/captions in Chromium. Touch input and tablet/phone dimensions are emulated. Physical iPad Safari and production-site browser access are not claimed. Rotation/reflow can naturally change wrapping; this feature prevents automatic seek/follow recentering, not layout changes from resizing or changing typography.
